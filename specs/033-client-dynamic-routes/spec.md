## Clarifications

- Q: 客户端拿什么路由？ → A: **独立合成段 + 动态路由**——成员只需获得通往「所在 zones 的合成段」的路径；真实网段永不出现在成员侧（grill「独立合成段+动态路由」决议）。
- Q: 谁是消费端？ → A: 全平台成员：Windows 客户端与 OpenWrt 客户端（后者既可宣告也可消费他人宣告）。
- Q: 服务端要改吗？ → A: 不改。服务端在 030 已把合成段并入成员 peer 的 AllowedIPs（服务器→成员方向早已就位）；本切片补的是**成员侧把流量送进隧道**的最后一步，宣告清单复用 030 既有查询接口聚合。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Windows 成员拨通伙伴的局域网 (Priority: P1)

Windows 用户所在的 zone 里，伙伴的路由器宣告了自家局域网（032）。此前用户即使知道替身地址也无法访问——他的电脑不知道这些地址要走隧道。本切片后：客户端在连接期间自动从服务器获知所在 zones 的全部替身网段，并把通往它们的路径配进本机隧道；用户直接访问替身地址（如 NAS 的 `100.100.X.50`）即可，宣告新增/撤回后路径在一个刷新周期内自动跟进，全程无需任何手动操作。

**Why this priority**: 这是整条 030–033 功能链面向最终用户的收口——Windows 用户是本产品的主要人群，此前宣告功能对他们是「服务器都准备好了但拨不出去」的中间态（030 已登记）。

**Independent Test**: CI（netns + 真服务端 + 用户态隧道集成测试既有装具）：成员连接后访问替身地址的流量进入隧道并往返成功；宣告撤回后一个刷新周期内不可达；面板能看到可达的宣告子网清单。

**Acceptance Scenarios**:

1. **Given** 成员已连接且所在 zone 有宣告，**When** 访问替身地址，**Then** 流量经隧道送达宣告方背后的目标主机并往返成功，成员无需任何配置。
2. **Given** 成员连接期间伙伴新增了一条宣告，**Then** 一个刷新周期内成员即可访问新替身网段（无需重连）。
3. **Given** 宣告被撤回（或本机离开该 zone），**Then** 一个刷新周期内对应路径移除，访问不再可达。
4. **Given** 成员断开隧道，**Then** 替身网段路径随隧道一并消失（不留系统级残留）。
5. **Given** 面板查看，**Then** 能看到「我可达的宣告子网」清单（替身网段、所属 zone、宣告者），与服务器一致。
6. **Given** 服务器暂时不可达，**Then** 既有路径保持不变（冻结），恢复后下一个刷新周期收敛。

---

### User Story 2 - OpenWrt 路由器作为消费者 (Priority: P2)

一台 OpenWrt 路由器（031 接入、可能同时是 032 宣告者）所在的 zone 里有其他成员的宣告。路由器的隧道同样自动获得通往这些替身网段的路径——路由器自身（及后续切片中它背后的 LAN）能访问伙伴的宣告子网。自己宣告的替身网段不绕隧道（本机已直连真实子网）。

**Why this priority**: 让 OpenWrt 端消费能力与 Windows 对齐（语义跨端一致，宪法 III）；复用 032 已有的对账循环，增量小。

**Independent Test**: CI（netns 全内核装具，032 e2e 演进）：两台"路由器"互为宣告者与消费者，各自访问对方替身地址往返成功；自己的替身网段不出隧道。

**Acceptance Scenarios**:

1. **Given** 路由器 daemon 运行中且 zone 内有他人宣告，**Then** 一个对账周期内路由器可访问对方替身地址（往返成功）。
2. **Given** 自己宣告的子网，**Then** 其替身网段不进隧道路径（访问自家设备走本地真实地址，不绕服务器）。
3. **Given** 他人宣告被撤回，**Then** 一个对账周期内路径移除。
4. **Given** `status`/宣告清单查看，**Then** 能区分「我宣告的」与「我可达的」子网。

---

### Edge Cases

- **替身网段与成员本机网络冲突**：某条替身网段恰与成员本机某网段重叠（罕见；服务器池统一规划）→ 跳过该条并明确告警（不致命、不影响其他路径），冲突消除后下一个刷新周期自动补上。
- **离开 zone 的同时存在路径**：离开后服务器侧 peer 即时收紧（030），成员侧路径在一个刷新周期内移除——窗口期内流量已被服务器拦断，本地残留路径无害。
- **连接建立瞬间**：连接成功即做一次立即刷新（不等首个周期）。
- **多 zone 重复**：同一宣告挂接多个 zone 时按替身网段去重，路径只配一条。
- **大量宣告**：路径数量与服务器宣告配额同量级（每用户 10 量级 × 成员数），刷新与配置开销对用户无感。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 成员客户端 MUST 在连接期间动态维护「所在 zones 全部宣告的替身网段」清单（聚合、按替身网段去重；OpenWrt 端排除本机自己宣告的条目）。
- **FR-002**: 清单中的每个替身网段 MUST 被配置为本机隧道的有效路径：发往该网段的流量进入隧道；新增宣告在一个刷新周期内可达，撤回/离开 zone 在一个刷新周期内不可达。
- **FR-003**: 刷新节奏 MUST 为：连接建立时立即一次 + 连接期间周期刷新（分钟内收敛量级，具体值 plan 定）；服务器不可达时跳过本轮、既有路径冻结、恢复后收敛。
- **FR-004**: 断开隧道 MUST 同时清除全部替身网段路径，系统层零残留；重新连接后自动重建。
- **FR-005**: 替身网段与本机网络冲突时 MUST 跳过该条并告警（其余路径不受影响）；冲突消除后自动补上。
- **FR-006**: 既有行为零回归：VPN 内成员互访（/32）、zone 隔离语义、028 自愈、032 宣告端行为均不变；本切片不为「LAN→成员」方向创造任何路径（单向性延续）。
- **FR-007**: 服务端 MUST 零改动（030 的成员侧查询接口与 peer AllowedIPs 机制已足够）。
- **FR-008**: Windows 面板 MUST 展示「我可达的宣告子网」清单（替身网段/所属 zone/宣告者节点名）；OpenWrt 端 MUST 在既有查看命令中区分「我宣告的」与「我可达的」。
- **FR-009**: 两端语义 MUST 跨端一致：同一 zone 状态下，Windows 与 OpenWrt 成员获得相同的可达集合（各自平台机制实现，行为对齐）。

### Key Entities

- **可达宣告清单（consumer view）**: 成员视角聚合的「所在 zones 全部宣告」：替身网段、所属 zone(s)、宣告者节点名；纯派生态，真源在服务器，随刷新周期收敛。
- **隧道路径（per-synthetic route）**: 每个替身网段对应的本机隧道路径配置；生命周期 = 「连接中 ∧ 清单含该网段 ∧ 无本地冲突」。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: CI 端到端（真实隧道与转发）：成员访问替身地址 100% 往返成功；撤回后一个刷新周期内 100% 不可达；新增宣告无需重连即可达。
- **SC-002**: OpenWrt 消费端 CI 端到端：互为宣告者/消费者的两节点各自访问对方替身地址往返成功；自己的替身网段不出隧道。
- **SC-003**: 断开→路径零残留；重连→自动恢复；全程零手动操作。
- **SC-004**: 现有全部自动化测试保持绿色（服务端零改动、031/032 命令零回归、Windows 既有连接行为零回归）。
- **SC-005**: 真机最终验收（功能链收口）：真实 Windows 客户端经替身地址访问真实 OpenWrt 路由器背后的 LAN 设备成功——TODO「设备路由宣告到区域」凭此勾销。

## Assumptions

- 030（服务端 peer AllowedIPs 已含合成段、成员可查 zone 宣告清单）、031（routerd）、032（宣告端）均已合并；本切片纯客户端增量，服务端零改动（FR-007）。
- Windows 端「把替身网段配进隧道」的具体机制（连接时纳入配置 + 运行期热更新或等效手段）由 plan 决定；spec 只约束行为（无需重连即生效、断开零残留）。
- OpenWrt 消费端复用 032 的 60s 对账循环节奏；Windows 端刷新节奏 plan 定（分钟内收敛）。
- 不做：LAN→成员方向、DNS、IPv6、宣告端行为变更、服务端聚合新端点（复用既有查询）。
