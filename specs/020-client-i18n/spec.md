# Feature Specification: client-i18n

**Feature Branch**: `020-client-i18n`

**Created**: 2026-06-07

**Status**: Draft

**Input**: User description: "客户端 GUI 中/英双语汉化：Fyne lang 包，zh-Hans+en，启动按系统 locale，向导顶部+面板页脚可手动切换，重启生效，偏好存 Fyne Preferences"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 界面随系统语言自动呈现 (Priority: P1)

一名中文系统的用户首次启动客户端,看到的首次设置向导与主面板全部是中文;一名英文系统的用户启动同一个客户端,看到的是英文。用户无需做任何设置,界面语言就与其操作系统一致。

**Why this priority**: 这是「汉化」诉求的核心价值——中文用户开箱即得中文界面。没有它,后两个故事(手动切换、跟随系统复位)都失去依附对象。单独交付即是一个完整可用的双语客户端。

**Independent Test**: 在中文 locale 环境构建并启动 GUI,确认向导/面板可见文案为中文;在英文 locale 环境启动同一二进制,确认为英文。两套 catalog 的键集合一致(自动化校验)。

**Acceptance Scenarios**:

1. **Given** 操作系统语言为简体中文且从未设置过语言偏好, **When** 用户启动客户端进入首次设置向导, **Then** 向导所有可见文案(标题、按钮、字段标签、错误提示)显示为简体中文。
2. **Given** 操作系统语言为英文且从未设置过语言偏好, **When** 用户启动客户端, **Then** 界面所有可见文案显示为英文。
3. **Given** 用户已完成设置进入主面板, **When** 触发一个会返回错误的操作(如证书错误、连接失败), **Then** 展示给用户的错误文案为当前界面语言的人类可读句子(非英文 Go error 链)。
4. **Given** 任一语言, **When** 检视两套翻译目录, **Then** 简体中文与英文的翻译键集合完全相同,无任一侧缺键。

---

### User Story 2 - 手动选择界面语言(重启生效) (Priority: P2)

用户的系统语言与其偏好不一致(例如英文系统但想用中文界面),希望手动把界面切到指定语言。用户在向导顶部或面板页脚的语言下拉中选择「中文」或「English」,得到「下次启动生效」的提示;重启后界面变为所选语言,且该选择跨重启保留。

**Why this priority**: 覆盖系统语言 ≠ 用户偏好的场景,是双语能力的必要补全;但相较「跟随系统」属于少数用户路径,故 P2。

**Independent Test**: 在某一 locale 启动,通过选择器选中另一语言,确认出现「重启生效」提示;重启后界面为所选语言;再次重启仍保持该语言(偏好已持久化)。

**Acceptance Scenarios**:

1. **Given** 英文界面, **When** 用户在向导顶部语言下拉选择「中文」, **Then** 界面提示「该设置将在下次启动后生效」,当前界面不立即重绘。
2. **Given** 用户已选「中文」并重启, **When** 客户端启动, **Then** 界面为简体中文,无视系统 locale 为英文。
3. **Given** 已手动选定某语言, **When** 用户再次完全退出并启动客户端, **Then** 界面仍为上次所选语言(偏好持久保留)。
4. **Given** 主面板页脚的语言下拉, **When** 用户在面板处切换语言, **Then** 行为与向导处一致(同一偏好读写、同样的重启生效提示)。

---

### User Story 3 - 复位为「跟随系统」 (Priority: P3)

曾手动指定过语言的用户想退回到「跟随系统」。用户在语言下拉中选择「跟随系统」,清除此前的语言偏好;重启后界面重新按操作系统语言呈现。

**Why this priority**: 让手动覆盖可逆,是选择器的闭环;属于已设置覆盖后的回退路径,使用频次最低,故 P3。

**Independent Test**: 先手动选定一种与系统不同的语言并重启确认生效;再选「跟随系统」并重启,确认界面回到系统 locale 对应的语言。

**Acceptance Scenarios**:

1. **Given** 用户此前手动选过「中文」(系统为英文), **When** 用户在语言下拉选择「跟随系统」, **Then** 出现重启生效提示且语言偏好被清除。
2. **Given** 已选「跟随系统」并重启, **When** 客户端启动, **Then** 界面按操作系统 locale 呈现(此例为英文)。
3. **Given** 从未设置过偏好的新安装, **When** 用户打开语言下拉, **Then** 当前选中项为「跟随系统」(首次默认)。

---

### Edge Cases

- **未受支持的系统 locale**(既非中文亦非英文,如法语):按英文呈现(默认回退语言)。
- **偏好值损坏或为未知语言**:视同未设置,回退「跟随系统」。
- **某条文案在所选语言缺翻译**:回退到该键的默认(英文)文案,不显示原始键名或空白。两套目录键集一致的自动化校验用于在交付前阻断此情况。
- **用户选了与当前相同的语言**:不报错,可仍给出(或抑制)重启提示,界面不变。
- **错误文案的语言**:typed-error 映射在 UI 层完成,故错误句子始终与界面语言一致,即便错误源自底层英文 error。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 客户端 GUI MUST 提供简体中文(zh-Hans)与英文(en)两套界面文案,覆盖 `internal/client/ui/` 下所有用户可见字符串,包括界面文案与 typed-error 映射层(`friendly` / `panelMessage` / `tunnelMessage`)产生的错误提示。
- **FR-002**: 启动时,在用户从未设置语言偏好的情况下,客户端 MUST 依据操作系统 locale 选择界面语言:中文系统→中文,其余→英文(英文为默认回退)。
- **FR-003**: 用户 MUST 能在首次设置向导顶部与主面板页脚分别看到一个语言选择器,两处呈现相同的三个选项「跟随系统 / English / 中文」并读写同一份语言偏好。
- **FR-004**: 当用户手动选择某一具体语言时,客户端 MUST 持久化该选择,使其跨重启保留,并在下次启动时让该选择**压过**系统 locale。
- **FR-005**: 当用户选择「跟随系统」时,客户端 MUST 清除已保存的语言偏好,使下次启动重新按系统 locale 呈现。
- **FR-006**: 语言变更 MUST 在下次启动生效;选择后客户端 MUST 给出「下次启动后生效」的明确提示,且 MUST NOT 在运行时实时重绘当前界面。
- **FR-007**: 语言偏好 MUST 存储在与 onboarding 状态解耦、且在首次向导(本地状态记录尚不存在)阶段即可读取的位置;MUST NOT 写入本地状态记录(state.json)。
- **FR-008**: 两套翻译目录 MUST 保持键集合一致;任一语言缺失某键时,该处文案 MUST 回退到默认(英文)文案,绝不展示原始键名或空白。
- **FR-009**: 本特性 MUST NOT 改动服务端或底层非 UI 的字符串(散落的 `errors.New` 等),维持「用户可见字符串只在 UI 层映射」的边界。

### Key Entities *(include if feature involves data)*

- **语言偏好 (Language Preference)**: 表示用户对界面语言的选择。取值为「未设置(=跟随系统)」「中文(zh-Hans)」「英文(en)」三态之一。存于与本地设置状态解耦的客户端偏好存储中,在 app 初始化后、首次向导之前即可读取。
- **翻译目录 (Translation Catalog)**: 每种语言一份的「键→本地化文案」集合。两份目录的键集合必须一致。英文目录同时充当任何缺失键的回退来源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在中文系统上全新启动(无偏好),向导与面板 100% 的用户可见文案为中文;在英文系统上为 100% 英文。
- **SC-002**: 用户从打开语言选择器到选定目标语言的操作 ≤ 3 次点击,且在选定后立即(≤ 1 秒)看到「下次启动生效」提示。
- **SC-003**: 手动选定的语言在连续两次完整重启后仍然保持(偏好持久化成功率 100%)。
- **SC-004**: 简体中文与英文翻译目录的键集合差异为 0(自动化校验通过);无任何用户可见界面残留未翻译的占位键名。
- **SC-005**: 引入翻译机制后,既有无头测试套件(`unshare -rUn go test ./...`)保持全绿,服务端与底层(SQLite/nftables/WireGuard)行为零改动。

## Assumptions

- **重启方式**:语言变更采用「提示用户、下次启动生效」,不做强制自动重启——VPN 客户端自动重启会意外中断隧道,手动重启更安全且实现更简单。
- **支持语言**:v1 仅简体中文 + 英文两种;繁体、其他语言不在范围。
- **默认/回退语言**:英文为未受支持 locale 及缺失键的统一回退。
- **翻译范围**:仅 `internal/client/ui/`(约 180 个用户可见字符串)。控制器层(panel、onboard)只回传 typed error,字符串映射集中在 UI 层,边界干净,无需改动控制器。
- **偏好存储介质**:复用客户端既有的应用级偏好存储(app 已有稳定应用 ID),在 `app.New` 之后即可读取,先于本地状态记录存在。
- **运行时切换**:不提供运行时实时换语言;选完即提示重启。
- **GUI 构建标签**:界面代码位于 `//go:build gui` 之下;语言解析与目录校验逻辑应尽量下沉到可无头测试的纯逻辑,GUI 部分以 Windows 手工验收矩阵(写入 quickstart.md,同 018 风格)覆盖。
