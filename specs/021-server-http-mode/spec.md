# Feature Specification: server-http-mode

**Feature Branch**: `021-server-http-mode`

**Created**: 2026-06-07

**Status**: Draft

**Input**: User description: "服务端可选明文 HTTP 监听（供反向代理终止 TLS）：`[server] tls = false` 才走明文，默认仍 HTTPS，缺 cert 仍硬失败，现存配置不静默降级；HTTP 模式 + 非回环地址打 WARN 不拦；仅服务端，客户端零改动。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在反代后以明文 HTTP 运行服务端 (Priority: P1)

一名运维在 nginx / Caddy 等反向代理后部署 lanweave 服务端，由反代统一终止 TLS。运维在服务端配置中显式关闭 TLS，使服务端只监听本地明文 HTTP；反代将外部 HTTPS 请求转发到服务端明文端口，所有受保护的控制面调用（注册 / 登录 / node / zone 管理）照常工作，数据面 WireGuard 不受影响。

**Why this priority**: 这是本特性的核心价值——让已经在用反代终止 TLS 的部署不必再让服务端重复持有/管理证书。没有它，后两个故事（默认仍 HTTPS 的安全保证、绑定告警）都失去依附对象。单独交付即是一个可用的「反代友好」服务端。

**Independent Test**: 用显式关闭 TLS 的配置启动服务端，以明文 HTTP 客户端打通一条需要鉴权的端点（如登录后调 `/me`），确认无需任何证书即可正常响应；同一份二进制在 WireGuard / nftables 正常 boot 的前提下运行。

**Acceptance Scenarios**:

1. **Given** 配置显式设置「关闭 TLS」, **When** 启动服务端, **Then** 服务端在配置地址上监听明文 HTTP，不要求任何证书/私钥即可启动成功。
2. **Given** 服务端运行在明文 HTTP 模式, **When** 明文 HTTP 客户端完成登录并携带 bearer token 调用受保护端点, **Then** 请求被正常鉴权与响应（与 HTTPS 模式行为一致）。
3. **Given** 明文 HTTP 模式且配置中存在（未使用的）证书/私钥路径, **When** 启动服务端, **Then** 证书/私钥被忽略，启动不因证书可读性而失败。

---

### User Story 2 - 默认与既有配置始终保持 HTTPS（绝不静默降级） (Priority: P1)

一名运维把服务端升级到含本特性的新版本，其现有配置文件**从未提及** TLS 开关。升级后服务端必须仍以 HTTPS 监听，绝不能因为新增了「可关 TLS」能力而把未表态的旧配置悄悄降级成明文。同样，在 TLS 模式下若证书缺失或损坏，服务端必须硬失败而非退回明文。

**Why this priority**: 这是本特性的安全护栏，与 US1 同等关键（P1）。一个「能关 TLS」的开关若零值不安全，会让所有未改配置的现网部署在升级后默默暴露明文——这是不可接受的回归。故安全默认与 US1 的新能力必须一并交付。

**Independent Test**: 用一份完全不含 TLS 开关的既有配置启动，确认服务端走 HTTPS；把 TLS 模式下的证书改为缺失/不可读，确认启动硬失败并报清晰错误，不退回明文。

**Acceptance Scenarios**:

1. **Given** 一份不包含 TLS 开关键的既有配置, **When** 升级后启动服务端, **Then** 服务端以 HTTPS 监听（与升级前行为一致），不进入明文模式。
2. **Given** 配置显式启用 TLS（或采用默认 TLS）但证书/私钥缺失或不可读, **When** 启动服务端, **Then** 启动**硬失败**并给出可理解的错误，**不**静默降级为明文 HTTP。
3. **Given** 配置显式启用 TLS 且证书/私钥可读, **When** 启动服务端, **Then** 服务端以 HTTPS 监听，行为与本特性引入前完全一致。

---

### User Story 3 - 明文绑定非回环地址时的启动告警 (Priority: P2)

一名运维在明文 HTTP 模式下把服务端绑定到非回环地址（如 `0.0.0.0` 或某网卡 IP）。服务端在启动时打印一条警告，提示该明文监听应置于 TLS 终止反代之后、不要直接暴露到公网；但服务端**不拦截**启动——以兼容「反代作为独立容器、需绑 `0.0.0.0` 才能跨容器访问」的 Docker 等部署形态。

**Why this priority**: 降低误配置导致明文暴露公网的风险，是有价值的安全提示；但属告警而非阻断，且仅在已选择明文模式的子场景触发，故 P2。

**Independent Test**: 在明文模式下分别用回环地址与非回环地址启动，确认仅后者产生一条启动告警，且两种情况下服务端均成功启动并对外服务。

**Acceptance Scenarios**:

1. **Given** 明文 HTTP 模式且绑定地址为非回环（含 `0.0.0.0`）, **When** 启动服务端, **Then** 启动日志出现一条 WARN 级别提示（需置于反代后、勿暴露公网），且服务端仍正常启动。
2. **Given** 明文 HTTP 模式且绑定地址为回环（如本机环回）, **When** 启动服务端, **Then** **不**产生该告警，服务端正常启动。
3. **Given** HTTPS 模式（任意绑定地址）, **When** 启动服务端, **Then** 不产生该明文告警。

---

### Edge Cases

- **未提及 TLS 开关的旧配置**：视同启用 TLS（HTTPS），不降级（US2-1，安全默认）。
- **TLS 模式缺/坏证书**：硬失败，不退回明文（US2-2）。
- **明文模式但配了证书路径**：忽略证书，正常以明文启动（US1-3）。
- **明文模式绑 `0.0.0.0` 或公网 IP**：告警但不拦截（US3-1）。
- **明文模式绑回环**：无告警，视为推荐的反代本地回环部署（US3-2）。
- **客户端连接**：客户端始终连反代的 `https://` 公网地址，其证书/TOFU/`--insecure` 行为不因服务端是否明文而改变（本特性不触及客户端）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 服务端 MUST 提供一个**显式**的传输模式开关，使运维可选择监听明文 HTTP 而非 HTTPS。
- **FR-002**: 该开关的「未设置 / 零值」MUST 解析为 **HTTPS（TLS 开启）**；任何不显式选择明文的配置（含完全不提及该开关的既有配置）MUST 以 HTTPS 监听，绝不静默降级为明文。
- **FR-003**: 当且仅当运维**显式**选择明文模式时，服务端 MUST 监听明文 HTTP，并 MUST NOT 要求任何证书/私钥即可启动。
- **FR-004**: 在 TLS（HTTPS）模式下，证书/私钥缺失、不可读或无效时，服务端 MUST 启动硬失败并给出可理解的错误，MUST NOT 退回明文监听。
- **FR-005**: 在明文 HTTP 模式下，服务端 MUST 忽略证书/私钥配置项（其缺失或不可读 MUST NOT 阻止启动）。
- **FR-006**: 在明文 HTTP 模式下，若绑定地址为非回环地址（含 `0.0.0.0`），服务端 MUST 在启动时记录一条警告级日志，提示应置于 TLS 终止反代之后且勿暴露公网；该告警 MUST NOT 阻止启动。
- **FR-007**: 在明文 HTTP 模式下绑定回环地址，或在 HTTPS 模式下（任意地址），服务端 MUST NOT 产生上述明文告警。
- **FR-008**: 明文 HTTP 模式 MUST NOT 改变任何控制面业务语义——鉴权、限流、各 REST 端点的行为与响应在两种传输模式下 MUST 一致。
- **FR-009**: 本特性 MUST NOT 改动客户端、WireGuard 数据面或打包安装时的证书生成/默认配置；打包默认仍生成自签证书并以 HTTPS 启动，明文模式仅经运维手动修改配置启用。
- **FR-010**: 项目设计文档与示例配置 MUST 与新行为保持一致：放宽控制面「全部 HTTPS」措辞为「HTTPS，或 TLS 终止反代后的明文 HTTP」；在已知风险登记中新增一条接受项（仅显式开启才明文、须上游 TLS、勿暴露明文监听公网）；修正示例配置中「仅 HTTPS、无明文监听」的失实注释。

### Key Entities *(include if feature involves data)*

- **传输模式开关 (Transport Mode Setting)**: 服务端配置中的一项，表示控制面监听 HTTPS 还是明文 HTTP。取「HTTPS（默认 / 未设置 / 零值）」与「明文 HTTP（仅显式选择）」两态。其安全不变量是：未表态一律解析为 HTTPS。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在显式明文模式下启动后，明文 HTTP 客户端对一条受保护端点的鉴权调用 100% 成功，全程无需任何证书。
- **SC-002**: 用一份不含传输模式开关的既有配置升级启动，服务端 100% 以 HTTPS 监听（明文降级发生率为 0）。
- **SC-003**: 在 TLS 模式下证书缺失/损坏时，启动失败率为 100%（绝不出现退回明文继续服务的情况）。
- **SC-004**: 明文模式绑定非回环地址时，启动告警出现率为 100%；绑定回环或 HTTPS 模式时该告警出现率为 0。
- **SC-005**: 引入本特性后，既有无头测试套件保持全绿，客户端与 WireGuard / nftables 行为零改动。

## Assumptions

- **反代终止 TLS**：明文模式的预期部署是「外部 HTTPS 由 nginx / Caddy 等反代终止，反代将明文转发到服务端本地端口」。控制面 REST 无状态、用 bearer token，不依赖自身 scheme；数据面 WireGuard 始终加密——反代终止 TLS 不破坏任何服务端逻辑（已核验：限流为全局而非按-IP；无 cookie / secure flag / 请求级 TLS 判定 / 绝对 URL 逻辑；客户端地址仅用于访问日志）。
- **显式开关、安全零值**：采用「默认/未设置=HTTPS，仅显式值才明文」的语义，确保升级既有配置不降级（本特性最关键的硬约束）。
- **告警不拦截**：非回环明文绑定仅告警，以兼容反代作为独立容器、需绑 `0.0.0.0` 的部署。
- **打包不变**：postinstall 照旧生成自签证书、默认 HTTPS；运维手动改配置启用明文，未用到的自签证书无害留存。
- **客户端零改动**：客户端仍连反代公网 `https://` 地址，TOFU / 证书 / `--insecure` 逻辑不变。
- **`X-Forwarded-For` / 可信代理转发不在范围**：限流本就全局、无安全影响；明文模式下访问日志记录的是代理 IP，作为已知小限制接受。
