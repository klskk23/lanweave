### User Story 1 - 主页面 Hero 卡片:一眼看清本机状态并一键连/断 (Priority: P1)

一名已完成 onboarding 的用户打开客户端主页面。页面顶部是一张「本设备」Hero 卡片:一行状态指示(一个彩色圆点 + 「已连接 / 正在连接 / 未连接 / 连接失败」文本,而非 `[在线]` 之类括号文本)、设备名、等宽字体显示的 VPN IP;卡片底部是**单一主按钮**,根据当前状态在「立即连接」与「断开连接」之间切换(取代旧的连接、断开两个并排按钮);其下一条分隔线 + 「允许 VPN 入站访问」Switch 行(替代旧的 checkbox)与其 CIDR 副标题。整个界面为强制深色、扁平(无渐变 / 阴影 / glow)的品牌化外观。

**Why this priority**: Hero 卡片 + 单一主按钮 + 状态圆点是本次改版的视觉核心,直接消灭旧界面最被诟病的三处(括号状态文本、双连接按钮、checkbox 开关)。它是自定义深色主题的首个落地载体,单独交付即可演示「焕然一新且操作更清晰」的主面板,后续故事(App Bar、列表、流量、Wizard)都依附于这套主题与卡片骨架。

**Independent Test**: 在装好的客户端上打开主面板,肉眼确认 Hero 卡片呈现状态圆点(非括号)、设备名、等宽 IP、单一主按钮;点击主按钮可在连接/断开间切换且按钮文案随之改变;Switch 的开/关与防火墙偏好一致;无头控件测试断言「按连接状态渲染出唯一的连或断按钮」「Switch 反映 firewall 偏好」。

**Acceptance Scenarios**:

1. **Given** 客户端处于未连接状态, **When** 打开主面板, **Then** Hero 卡片显示「未连接」状态(圆点 + 文本)、设备名、等宽 VPN IP,且只有一个「立即连接」主按钮(不出现第二个连接/断开按钮)。
2. **Given** 隧道已连接, **When** 查看 Hero 卡片, **Then** 状态显示「已连接」(圆点 + 文本),主按钮变为「断开连接」,点击后隧道断开、状态与按钮回到未连接态。
3. **Given** 主面板已打开, **When** 切换「允许 VPN 入站访问」Switch, **Then** 防火墙偏好随之落库与应用(开=添加放行规则、关=删除),Switch 状态与底层偏好始终一致,旁边显示 `100.127.0.0/16` CIDR 副标题。
4. **Given** 任意状态, **When** 观察整个界面, **Then** 配色为强制深色、品牌色一致、扁平无渐变/阴影/glow,与系统明暗设置无关。

### User Story 2 - App Bar 与 overflow 菜单:品牌头 + 语言 / 退出 / 信任状态归位 (Priority: P2)

用户在主面板顶部看到一条 48px 的 App Bar:左对齐的 logo + 「lanweave」字样(非居中标题),底部一条细分隔线;右侧一个 ⋮ overflow 菜单。点开菜单可切换界面语言(跟随系统 / 中文 / English,重启生效)、执行「退出登录」(红色、位于菜单底部、远离主操作防误点)。当处于不受系统 CA 信任的会话时,菜单内出现信任状态项——`--insecure` 会话显示红色「证书未验证」,自签但已在本机钉扎(TOFU)的会话显示中性「已在本机信任」;不再使用旧的常驻警告条。

**Why this priority**: App Bar 与 overflow 重构了导航并把语言、退出登录、信任状态三处现有功能收纳进统一入口,使主界面更整洁。它是结构性改造,价值高但不及 Hero 卡片的视觉核心,故 P2。

**Independent Test**: 打开主面板确认 App Bar 左对齐 logo + lanweave + 底部 divider;点开 ⋮ 看到语言子菜单(三项)与置底的红色「退出登录」;在 insecure 会话下确认菜单出现红色「证书未验证」项,在 TOFU 钉扎会话下确认出现中性「已在本机信任」项;选「退出登录」走原有退登编排(断连 + 注销本机 node + 回 wizard)。

**Acceptance Scenarios**:

1. **Given** 主面板已打开, **When** 观察顶部, **Then** App Bar 左对齐显示 logo + 「lanweave」、底部有 0.5px 分隔线,标题不居中。
2. **Given** App Bar 的 ⋮ 菜单, **When** 点开, **Then** 含语言切换(跟随系统 / 中文 / English)与置底的红色「退出登录」项;选语言后提示重启生效,选退出登录执行既有退登流程(行为不变)。
3. **Given** 当前会话经 `--insecure` 建立, **When** 打开 ⋮ 菜单, **Then** 出现红色「证书未验证」菜单项(不再有常驻警告条)。
4. **Given** 当前会话为自签证书且已 TOFU 钉扎, **When** 打开 ⋮ 菜单, **Then** 出现中性「已在本机信任」菜单项。

### User Story 3 - 节点 / 区域 Tabs、列表与区域详情 (Priority: P2)

用户在 Hero 卡片下方看到两个标签「节点 N」「区域 N」(带计数,选中项有 2px 品牌青色指示条)。节点列表每行是 avatar(右下角状态点) + 设备名 + 等宽 IP;离线节点在 IP 后拼接「N 分钟前离线」;本机所在行额外带「本机」chip 与高亮背景,且**纯展示不可点击**。区域列表每行是扁平 avatar + 区域名 +(自己是 owner 时的)owner chip,**整行可点击 → 打开区域详情**,在详情内完成查看成员、退出、改密、删除、踢人等操作。主面板右下角有一个「+」FAB,点击弹出「创建区域 / 加入区域」二选一。

**Why this priority**: 列表与区域详情承载主要的内容浏览与区域管理操作,是日常使用的主体;但视觉与交互依附于已建立的主题与卡片骨架,故 P2(在 Hero 之后)。

**Independent Test**: 打开主面板确认两个 tab 带计数与青色指示条;节点行显示 avatar + 状态点 + 名 + 等宽 IP,本机行有「本机」chip + 高亮且点击无响应,离线行显示「N 分钟前离线」;点击某区域行打开详情并能在其中改密 / 踢人 / 删除(owner) 或只读查看成员(非 owner);点「+」FAB 出现创建 / 加入二选一。

**Acceptance Scenarios**:

1. **Given** 名下有多个节点, **When** 打开「节点」tab, **Then** 每行显示 avatar + 右下状态点 + 设备名 + 等宽 IP;tab 标题含节点计数,选中态有 2px 品牌青色指示条。
2. **Given** 某节点离线且有历史握手时间, **When** 查看其行, **Then** IP 后显示「N 分钟前离线」(数据取自现有设备视图的 LastSeen)。
3. **Given** 本机对应的节点行, **When** 查看并点击, **Then** 该行带「本机」chip 与高亮背景,且点击不进入任何详情(纯展示)。
4. **Given** 「区域」tab 列出我所在的区域, **When** 点击某一区域行, **Then** 打开该区域详情;我是 owner 时可在内改密 / 踢人 / 删除区域 / 退出,非 owner 时只读查看成员并可退出。
5. **Given** 主面板, **When** 点击右下角「+」FAB, **Then** 弹出「创建区域 / 加入区域」二选一入口,分别进入既有的创建 / 加入流程。

### User Story 4 - Hero 卡片实时上下行流量 (Priority: P3)

隧道连接后,用户在 Hero 卡片状态行看到实时的上行(↑)与下行(↓)流量计数;断开连接后流量隐藏并复位。

**Why this priority**: 流量计数提升「连接确有数据在走」的可感知度,是锦上添花;且它是本切片唯一需要触达隧道 / WG 引擎引入新数据源(当前隧道不暴露收发字节)的部分,改动面与风险独立于纯 UI 故事,故单列 P3。

**Independent Test**: 连接隧道后观察 Hero 出现 ↑ / ↓ 数值并随流量增长刷新;断开后该区隐藏并复位;无头测试断言字节数到可读单位(如 KB/MB)的格式化函数正确。

**Acceptance Scenarios**:

1. **Given** 隧道未连接, **When** 查看 Hero 卡片, **Then** 不显示流量数值。
2. **Given** 隧道已连接且有数据往来, **When** 观察 Hero 状态行, **Then** 显示 ↑(上行)与 ↓(下行)字节计数,并以较连接前更快的节奏刷新。
3. **Given** 隧道处于已连接并显示流量, **When** 断开连接, **Then** 流量数值隐藏并复位(再次连接重新显示)。

### User Story 5 - Wizard 套用同一深色主题 (Priority: P3)

首次启动或退出登录后,用户进入 Wizard。Wizard 沿用与主面板一致的深色品牌主题:相同配色、字号层级、pill 主按钮、卡片包裹的内容区,顶部保留语言选择器。四步流程(服务器地址 → 登录/注册 → 节点名 → 配置)与 Back / Cancel / Next 逻辑完全不变。

**Why this priority**: 视觉统一性收尾,价值真实但最低——纯换肤、零流程改动,且依赖主题已就绪,故 P3。

**Independent Test**: 全新环境启动进入 Wizard,肉眼确认其配色 / 字号 / pill 按钮 / 卡片外观与主面板一致、顶部有语言选择器;走完四步流程与上一版完全一致(注册 / 登录 / 建节点成功进入主面板),无任何步骤或行为变化。

**Acceptance Scenarios**:

1. **Given** 全新环境启动, **When** 进入 Wizard, **Then** 其外观(深色品牌主题、字号、pill 主按钮、卡片包裹 body、顶部语言选择器)与主面板风格一致。
2. **Given** Wizard 任意步骤, **When** 操作 Back / Cancel / Next 并走完四步, **Then** 流程与改版前完全相同(服务器 → 登录/注册 → 节点名 → 配置),成功后进入主面板。

---

### Edge Cases

- **未连接 / 断开后的流量行**:不显示;断开时复位,不残留上一会话数值(US4-1、US4-3)。
- **离线节点缺历史握手**:LastSeen 为空 / 无效时只显示「离线」,不拼接相对时间(US3-2 的退化)。
- **本机节点行**:点击无响应,不进入任何详情(US3-3)。
- **信任状态互斥**:同一会话只会是「系统 CA 通过(无信任项)」「TOFU 已钉(中性项)」「insecure(红项)」三者之一,不同时出现(US2-3/4)。
- **非 owner 打开区域详情**:只读成员列表 + 退出按钮,无改密 / 踢人 / 删除入口(复用现有 owner 判定)(US3-4)。
- **空列表**:节点 / 区域计数为 0 时 tab 仍显示且列表为空,不报错。
- **窄窗口**:App Bar / Hero / tabs / 列表在现有窗口尺寸下不溢出、不裁切。
- **语言切换**:沿用既有「重启生效」语义,菜单内选择后提示重启,不做运行时实时重绘。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 客户端 MUST 应用一套自定义品牌主题(品牌色 / 字号层级 / 间距),**强制深色**并忽略系统明暗设置;整体观感 MUST 扁平——MUST NOT 出现渐变、阴影或 glow。
- **FR-002**: 主面板顶部 MUST 有一条 App Bar,左对齐显示 logo + 「lanweave」并在底部有一条细分隔线;标题 MUST NOT 居中。
- **FR-003**: App Bar 右侧 MUST 提供一个 overflow(⋮)菜单,内含语言切换(跟随系统 / 中文 / English,重启生效)与置底的红色「退出登录」项;退出登录 MUST 复用既有退登编排(断连 + 注销本机 node + 清凭据 + 回 wizard),行为不变。
- **FR-004**: 信任状态 MUST 收纳进 overflow 菜单:`--insecure` 会话显示红色「证书未验证」项,自签且已 TOFU 钉扎的会话显示中性「已在本机信任」项;MUST NOT 再使用常驻警告条。
- **FR-005**: 主面板 MUST 有一张「本设备」Hero 卡片,含状态行(一个彩色圆点 + 文本,覆盖已连接 / 正在连接 / 未连接 / 连接失败)、设备名、等宽字体的 VPN IP;状态 MUST NOT 用 `[...]` 括号文本表示。
- **FR-006**: Hero 卡片 MUST 提供**单一**主按钮,按当前隧道状态在「连接」与「断开」之间切换;MUST NOT 同时呈现独立的连接与断开两个按钮。
- **FR-007**: Hero 卡片 MUST 含一个「允许 VPN 入站访问」Switch(MUST NOT 用 checkbox)及其 `100.127.0.0/16` CIDR 副标题;Switch 状态 MUST 与防火墙偏好双向一致,切换即落库并应用(开=放行、关=移除)。
- **FR-008**: 主面板 MUST 提供「节点 N」「区域 N」两个带计数的 tab,选中态有 2px 品牌青色指示条;tab 名 MUST 为「节点 / 区域」,MUST NOT 用「我的节点 / 我的区域」之类措辞。
- **FR-009**: 节点列表每行 MUST 显示 avatar(带右下状态点) + 设备名 + 等宽 IP;离线且有历史握手时 MUST 在 IP 后显示「N 分钟前离线」(数据取自现有设备视图 LastSeen);本机行 MUST 额外带「本机」chip 与高亮背景且 MUST NOT 可点击(纯展示)。
- **FR-010**: 区域列表每行 MUST 显示扁平 avatar + 区域名 +(owner 时的)owner chip;整行 MUST 可点击打开区域详情,在详情内完成查看成员 / 退出 / 改密 / 删除 / 踢人(owner 操作沿用既有 owner 判定与权限)。
- **FR-011**: 主面板 MUST 提供一个右下角「+」FAB,点击弹出「创建区域 / 加入区域」二选一,分别进入既有创建 / 加入流程。
- **FR-012**: 隧道连接期间,Hero 卡片 MUST 显示实时上行(↑)/ 下行(↓)流量字节并以较连接前更快的节奏刷新;断开时 MUST 隐藏并复位。流量数据 MUST 来自隧道 / WG 引擎新暴露的 per-peer 收发字节计数。
- **FR-013**: Wizard MUST 套用与主面板一致的深色主题(配色 / 字号 / pill 主按钮 / 卡片包裹 body),顶部保留语言选择器;其四步流程与 Back / Cancel / Next 逻辑 MUST 保持不变(仅换肤,零流程改动)。
- **FR-014**: 所有新增 / 改写的用户可见文案 MUST 同步提供 zh-Hans 与 en 双语(沿用既有 i18n 机制),包括但不限于:已连接 / 正在连接 / 未连接 / 连接失败、立即连接 / 断开连接、允许 VPN 入站访问、本机、N 分钟前离线、证书未验证 / 已在本机信任、上行 / 下行流量、节点 / 区域。
- **FR-015**: 本切片 MUST NOT 改变任何客户端业务语义——连接 / 断开、防火墙开关、退出登录、区域创建 / 加入 / 管理、i18n、TOFU / insecure 信任判定的行为与既有一致;唯一的非 UI 改动 MUST 限于隧道暴露流量计数一处。
- **FR-016**: 改版 MUST 满足 `docs/UI-DESIGN.md` §8 验收清单全部条目(App Bar 左对齐、单一主按钮、状态圆点非括号、avatar + 状态点、本机 chip、入站 toggle 在 Hero 内、Switch 非 checkbox、pill 按钮、等宽 IP、无渐变 / 阴影 / glow 等)。

### Key Entities *(include if feature involves data)*

- **流量统计 (Traffic Stats)**: 隧道 / WG 引擎暴露的 per-peer 收发字节(上行 / 下行),为瞬时数据,仅在连接期间有效,断开复位。本切片唯一的新数据源。
- **设备视图 (Device View)**: 现有结构,含设备名、VPN IP、在线状态、LastSeen(上次握手,RFC3339)、是否本机。改版复用其字段(尤以 LastSeen 驱动「N 分钟前离线」),不新增后端字段。
- **信任状态 (Trust Status)**: 当前会话的证书信任态,三选一——系统 CA 通过(无菜单项)/ TOFU 已钉(中性「已在本机信任」)/ insecure(红「证书未验证」),决定 overflow 菜单中的信任项呈现。
- **防火墙偏好 (Firewall Preference)**: 现有持久化偏好(允许 VPN 网段入站,默认关,来自 018),改版仅以 Switch 控件替代 checkbox 呈现同一偏好,语义不变。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 Mesa OpenGL 测试 VM 上对 `docs/UI-DESIGN.md` §8 验收清单逐条肉眼检查,12 项 100% 通过。
- **SC-002**: 每个 user story 至少 1 个 headless 控件测试通过(单按钮按状态切换、本机 chip + 高亮、Switch 反映防火墙偏好、流量字节格式化、区域行点击开详情)。
- **SC-003**: 主连接操作从「两个并排按钮里选对的」变为「单一按钮」:连接态界面只暴露断开、未连接态只暴露连接,消除选错按钮的可能。
- **SC-004**: 客户端既有无头测试套件保持全绿,连接 / 断开、防火墙、退出登录、区域管理、i18n 行为零回归。
- **SC-005**: `unshare -rUn go test ./...` 保持全绿(本切片不动 SQLite / nftables / WireGuard 服务端逻辑)。
- **SC-006**: 隧道连接后 Hero 出现非零上下行流量数值,断开后复位为不显示;字节到可读单位的格式化在无头测试中断言正确。

## Assumptions

- **控制器边界干净**:panel / onboard 控制器无 UI、只回传 typed error + 视图数据,本次改造集中在 `internal/client/ui/`,加上隧道暴露流量计数一处;客户端业务行为零回归是硬目标。
- **LastSeen 已存在**:设备视图已含 LastSeen(来自服务端上次握手时间),「N 分钟前离线」无需任何后端 / 协议改动。
- **防火墙偏好复用 018**:Switch 呈现的「允许 VPN 入站访问」即 018 引入的持久化偏好(默认关),只换控件不改语义与生命周期。
