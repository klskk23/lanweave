# Feature Specification: OpenWrt 宣告端（宣告 CLI + 地址翻译下发）

**Feature Branch**: `032-openwrt-announcer`

**Created**: 2026-06-11

**Status**: Draft

**Input**: User description: "032"（grill 共识 2026-06-11 的切片序列第三步：OpenWrt 宣告端——宣告 CLI + NETMAP/MASQUERADE 下发；依赖 030 服务端宣告控制面与 031 OpenWrt 客户端基础，两者均已合并）

## Clarifications

### Session 2026-06-11（grill 会话既定决策，本切片继承）

- Q: 地址翻译发生在哪？ → A: **宣告方路由器**上：目标地址 1:1 前缀翻译（合成段→真实段，主机位保留）+ 回程源伪装（成员 VPN 地址→路由器 LAN 地址），LAN 内主机零配置（grill 方案 B 核心机制）。
- Q: 方向性？ → A: 仅「zone 成员 → 宣告子网」单向发起（030 FR-013）；LAN 侧主动连成员永久不做。
- Q: 谁能宣告？ → A: platform=openwrt 节点（030 服务端门禁）；本切片就是该能力的客户端载体。
- Q: 翻译规则的真源？ → A: 服务端宣告清单（030 API）是唯一真源；路由器本地翻译规则是派生态，daemon 启动时全量对账重建（与服务端「SQLite 真源 + 派生态可重建」同一宪法原则的客户端镜像）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把家里的局域网宣告进 zone (Priority: P1)

路由器主人（已完成 031 接入、节点在某 zone 中）想让 zone 里的伙伴访问自己局域网中的设备（NAS、打印机、摄像头）。他在路由器上执行一条宣告命令，指定子网与目标 zone：服务器分配一个全服唯一的"替身"网段并回显映射关系；路由器自动配好地址翻译。此后 zone 成员拨打替身地址（主机位与真实地址一致，如真实 `.50` 对应替身 `.50`），流量经服务器转发到本路由器、翻译后送达局域网设备，回包原路返回——LAN 内设备零配置。

**Why this priority**: 这是 030–033 整条功能链的"最后一公里"：没有宣告端的翻译下发，030 的控制面只是无人消费的数据。

**Independent Test**: CI（netns + 真服务端 + 真内核 wg/nftables）：宣告命令后，模拟 zone 成员从隧道侧访问替身地址，流量被翻译并到达路由器 ns 内挂在"LAN"上的监听者，回包可达；映射关系在命令输出与列表中可见。

**Acceptance Scenarios**:

1. **Given** 已 onboard 的路由器节点在 zone Z 中，**When** 执行宣告命令（子网 + zone），**Then** 命令成功并回显「真实网段 → 替身网段」映射；服务器宣告清单出现该条目。
2. **Given** 宣告已生效，**When** zone Z 成员访问替身地址 X.Y.Z.50，**Then** 流量到达路由器局域网内真实地址 *.50 的设备，回包送回成员；LAN 设备无需任何配置（它看到的访问者是路由器自己）。
3. **Given** 宣告已生效，**When** 在路由器上查看宣告列表/状态，**Then** 能看到全部宣告的子网、替身网段与所属 zone。
4. **Given** 路由器重启（或 daemon 被拉起），**Then** 翻译规则依据服务器清单自动重建，宣告的子网恢复可达，无需人工。
5. **Given** 宣告被服务器拒绝（平台门禁/配额/子网非法/与自己已有宣告重叠/池耗尽/zone 非成员），**Then** 命令以非零退出码结束并输出与服务端错误对应的人类可读信息；本地不残留半套翻译规则。
6. **Given** 同一子网要分享给第二个 zone，**When** 对第二个 zone 再次宣告同一子网，**Then** 复用同一替身网段（030 语义），本地翻译规则不重复。

---

### User Story 2 - 撤回宣告与生命周期收口 (Priority: P2)

主人不想再分享某个子网：执行撤回命令——服务器侧该 zone 的挂接消失（最后一个挂接则整条宣告与替身段回收），路由器本地对应的翻译规则同步移除，zone 成员立即不可达。登出（031 的 logout）时，本地全部翻译规则一并清除（服务端级联由 030 负责）。

**Why this priority**: 没有干净的撤回与清场，宣告就是只进不出的债务；但其价值依附于 US1。

**Independent Test**: CI：撤回后成员访问替身地址超时、本地规则清零；多 zone 挂接只撤一个时另一 zone 照常；logout 后本地翻译规则零残留。

**Acceptance Scenarios**:

1. **Given** 子网已宣告至 zone Z，**When** 执行撤回命令，**Then** 服务器清单该挂接消失；zone Z 成员访问替身地址不再可达；该宣告若无其他 zone 挂接，本地翻译规则移除。
2. **Given** 同一子网挂接 Z1 与 Z2，**When** 仅撤回 Z1，**Then** Z2 成员照常可达（本地翻译规则保留，因替身段仍有效）。
3. **Given** 路由器执行 logout，**Then** 本地全部翻译规则清除（与隧道、凭据同场清理）；服务端宣告由 030 级联回收。
4. **Given** 服务器侧宣告被他人移除（zone owner 摘除 / zone 被删 / admin 级联），**When** daemon 周期对账或重启，**Then** 本地多余的翻译规则被清掉（派生态收敛于真源）。

---

### Edge Cases

- **宣告与撤回的本地/远端原子性**：远端成功而本地下发失败 → 命令报错并自动撤回远端挂接（不留「服务器有、路由器无」的黑洞宣告）；本地清理失败 → 警告 + 依靠 daemon 对账兜底。
- **daemon 未运行时的宣告命令**：允许（规则即刻下发不依赖 daemon）；但提示隧道未连接时成员暂不可达。
- **替身段与路由器自身网络冲突**：替身段由服务器从专用池分配（030 校验不与 VPN 池叠），但可能撞上路由器自己的某个本地网段——宣告命令检测到冲突时失败并提示（罕见；运维改池或改本地网段）。
- **多 LAN 路由器**：宣告操作者显式指定子网；不强制要求该子网直连本路由器（可为静态路由可达的下游网段），但输出提示「请确认本机可达该子网」。
- **fw4/防火墙共存**：翻译规则放在自有表中，不修改 OpenWrt 默认防火墙配置；与 fw4 共存性入实机矩阵。
- **对账周期内的窗口**：服务器侧被第三方移除后、对账前的窗口内本地规则仍在——流量已被服务器侧拦断（030 数据面先收口），本地多余规则无害，对账后清除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 路由器 CLI MUST 提供宣告管理命令族：宣告（子网 + zone）、撤回（指定宣告 + zone）、列出本机及所在 zones 的宣告（含真实网段/替身网段/所属 zone/宣告者）。沿用 031 的 CLI 形态（非交互、退出码、人类可读输出、字段稳定）。
- **FR-002**: 宣告成功 MUST 即刻在本机下发地址翻译：目标地址前缀 1:1 翻译（替身段→真实段，主机位不变）与回程源伪装（成员地址→路由器 LAN 侧地址），使 LAN 内主机零配置可达且回包经由原连接返回（030 既定机制）。
- **FR-003**: 撤回成功 MUST 即刻移除对应翻译规则；同一宣告仍挂接其他 zone 时翻译规则保留（替身段仍有效）。
- **FR-004**: 翻译规则 MUST 为派生态：唯一真源是服务器宣告清单。daemon 启动时 MUST 全量对账重建本地规则；运行期 MUST 周期对账（与健康检查同节奏量级），清除真源中已不存在的本地规则、补齐缺失的规则。
- **FR-005**: 远端宣告成功但本地下发失败时，命令 MUST 报错并补偿撤回远端挂接（不留服务器可路由、路由器不翻译的黑洞）；补偿亦失败时明确告警，交由 030 服务端状态与本机对账收敛。
- **FR-006**: 本地翻译规则 MUST 置于自有防火墙表内，不修改设备既有防火墙配置；logout MUST 清除本机全部翻译规则。
- **FR-007**: 服务端全部拒绝原因（platform 门禁、配额、子网非法、自身重叠、池耗尽、非 zone 成员、宣告功能停用）MUST 映射为人类可读信息 + 非零退出码；不产生任何本地半成品状态。
- **FR-008**: 宣告命令 MUST 校验替身段不与路由器本地任何网段冲突（冲突即失败并提示）；对「子网是否本机可达」仅提示不阻拦（下游路由场景合法）。
- **FR-009**: 单向性 MUST 保持：本切片的翻译仅服务「成员 → 宣告子网」方向的连接及其回包；不得为 LAN 侧主动发起创造路径（030 FR-013 的客户端侧呼应）。
- **FR-010**: 本切片 MUST NOT 改动服务端行为与 Windows 客户端（031 的 FR-013 延续）；031 既有命令行为不回归。
- **FR-011**: status/宣告列表 MUST 让主人无需查阅服务器即可知道：本机宣告了什么、替身网段是什么、翻译规则是否就位（与真源一致/对账中）。

### Key Entities

- **本机宣告（announcement, 客户端视角）**: 服务器宣告清单中 node=本机的条目；真实网段、替身网段、挂接 zones。客户端不持久化副本（真源在服务器，本地规则可重建）。
- **翻译规则（translation rules）**: 每条宣告对应的一组本机防火墙规则（前缀翻译 + 源伪装）；纯派生态，生命周期=「宣告存在 ∧ 对账确认」。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 端到端（CI netns，真内核转发与翻译）：宣告后，zone 成员访问替身地址对 LAN 监听者的往返 100% 可达；撤回后 100% 不可达；LAN 侧监听者全程零配置。
- **SC-002**: 重启/daemon 重建后，无人工干预下全部宣告的可达性自动恢复；服务器侧被第三方移除的宣告在一个对账周期内本地规则清除。
- **SC-003**: 宣告/撤回/列出全生命周期 100% 经 CLI 完成；全部服务端拒绝路径均以非零退出码 + 可操作信息结束，且本地零半成品。
- **SC-004**: 远端成功+本地失败的补偿路径有自动化验证：补偿后服务器清单无该挂接。
- **SC-005**: 现有全部自动化测试保持绿色（服务端、Windows 客户端、031 命令零回归）。
- **SC-006**: 真机 OpenWrt（含 fw4 默认防火墙）人工矩阵：宣告后另一客户端实测访问 LAN 设备成功；规则与 fw4 共存无冲突。

## Assumptions

- 依赖 030（服务端宣告 API/合成段分配/数据面）与 031（routerd CLI/daemon/隧道）均已合并交付；本切片纯客户端增量。
- 「成员侧能把流量送进隧道」对 Windows 端依赖 033（动态路由）；本切片 CI 用模拟成员（netns 内手配路由）验证端到端，与 030 e2e 同款手法。033 前，真实 Windows 成员暂不可达替身段——已知中间态（030 已登记）。
- 路由器 LAN 侧形态按 OpenWrt 常态假设（br-lan 等本地接口 + ip_forward 已开）；源伪装的出口地址取路由器在目标子网内的地址（直连场景）或路由器出口地址（下游路由场景）。
- 周期对账的节奏沿用 daemon 现有循环量级（15s 级），具体值 plan 阶段定；对账只比对本机相关条目。
- 不做：033 消费端动态路由（含 OpenWrt 自身作为他人宣告的消费者）、LAN→成员方向、DNS 名称、IPv6、LuCI 展示、.ipk 打包。
