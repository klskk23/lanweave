- Q: 同网段冲突怎么解？ → A: 方案 B 合成网段映射（隧道内只跑全服唯一合成段；真实网段永不进 cryptokey routing）。全服唯一性约束（方案 A）与每 zone 一接口（方案 C）被否决。
- Q: 谁能当宣告端？ → A: 仅 `openwrt` 平台节点（地址翻译须在宣告方路由器上做，Windows 无对应原语）；平台由客户端注册时自报，服务端按 platform 推导能力门禁。
- Q: 消费端策略？ → A: 独立合成段池 + 全平台动态路由（客户端改动属 033，本切片只负责把映射数据通过 API 暴露出去）。
- Q: 宣告权限？ → A: 任何成员可向所在 zone 宣告，无审批；配额兜底。
- Q: 控制面细节包？ → A: 全收——配额三态（默认 10/0=无限/admin 豁免）、合成段按（节点,真实子网）分配一次可挂多 zone、校验规则（RFC1918、/16–/30、不与两池重叠、同节点不互叠、跨节点允许重叠）、全链路级联回收。
- Q: 方向性？ → A: 仅「成员 → 宣告子网」单向发起；LAN 侧主动连成员永久不做。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 成员宣告子网，同 zone 成员经合成地址访问 (Priority: P1)

一位用户在家中部署了具备宣告能力的路由器节点（OpenWrt 平台），该节点已加入 zone。他把家中 LAN（如 `192.168.1.0/24`）宣告到这个 zone。服务端从合成段池为这条宣告分配一个等长的全服唯一合成段（如 `100.100.1.0/24`），并把数据面准备就绪：此后 zone 内任何成员把流量发往合成地址（如 `100.100.1.50`），服务端就会把它转发进宣告节点的隧道。成员通过查询接口能看到「真实网段 → 合成网段」的映射，知道该拨打哪个地址。

**Why this priority**: 这是功能的全部目的——没有「宣告 → 分配 → 数据面放行 → 映射可查」这条链，其余一切无意义。

**Independent Test**: 服务端集成测试（真 wg/nftables，netns 模拟宣告节点与成员节点）：成员 netns 内 ping 合成地址，包经服务器转发到达宣告节点 netns（其内配置等价的地址翻译），回包可达；查询 API 返回正确映射。

**Acceptance Scenarios**:

1. **Given** 一个 `openwrt` 平台节点已加入 zone Z，**When** 其主人把 `192.168.1.0/24` 宣告到 Z，**Then** 服务端返回分配的同长合成段，且该合成段不与任何已存在的合成段、VPN 池重叠。
2. **Given** 宣告已生效，**When** 查看服务端 WireGuard 状态，**Then** 宣告节点对应 peer 的 AllowedIPs 包含该合成段；**And** zone Z 的防火墙状态放行「Z 内成员 → 该合成段」的新建连接及其回程。
3. **Given** 宣告已生效，**When** zone Z 的成员（模拟节点）向合成段内某地址发起连接，**Then** 流量被转发进宣告节点的隧道；**And** 非 Z 成员发往该合成段的流量被丢弃（隔离不破）。
4. **Given** 宣告已生效，**When** 任何 Z 成员调用 zone 宣告清单接口，**Then** 响应包含宣告节点、真实网段、合成网段三元组。
5. **Given** 一个 `windows` 平台节点的主人尝试宣告子网，**Then** 请求被拒绝并返回明确的「平台不支持」错误。

---

### User Story 2 - 不同客户的相同真实网段互不干扰 (Priority: P2)

两位用户的家庭 LAN 恰好都是 `192.168.1.0/24`（极常见）。各自的路由器节点分别加入不同（甚至相同）的 zone 并都宣告这个网段。两条宣告各自获得不同的合成段，互不抢占、互不影响：各 zone 的成员通过各自的合成地址访问各自的目标网络。

**Why this priority**: 「真实网段允许任意冲撞」是选择合成映射方案的全部理由，是本功能区别于朴素实现的核心价值。

**Independent Test**: 集成测试中两个模拟节点宣告完全相同的真实网段（到不同 zone 与同一 zone 各测一例），断言两条宣告并存、合成段互异、各自数据面指向正确的 peer。

**Acceptance Scenarios**:

1. **Given** 节点 A（zone X）已宣告 `192.168.1.0/24` 获得合成段 S1，**When** 节点 B（zone Y）宣告同一真实网段，**Then** 宣告成功并获得合成段 S2 ≠ S1；**And** S1 仍然完整指向节点 A（无抢占）。
2. **Given** 同一 zone 内两个节点都宣告 `192.168.1.0/24`，**Then** 两条宣告并存、各有合成段，zone 宣告清单同时展示两条映射。
3. **Given** 同一节点已宣告 `192.168.1.0/24`，**When** 它再宣告 `192.168.1.128/25`（与自己已宣告网段重叠），**Then** 请求被拒绝（同节点宣告不得互叠）。
4. **Given** 节点 A 同时在 zone X 和 zone Y，已把 `192.168.1.0/24` 宣告到 X 获得合成段 S1，**When** 它把同一网段也宣告到 Y，**Then** 不再分配新段，Y 的清单复用 S1（按（节点,真实子网）只分配一次）。

---

### User Story 3 - 生命周期与级联回收 (Priority: P3)

宣告不是永久的：主人可以撤销；节点会退出 zone、被踢、被删除；用户会被管理员删除。任何一条路径之后，服务端的数据库、WireGuard peer 配置、防火墙状态都不得残留该宣告的任何痕迹，回收的合成段可被后续宣告复用。服务端重启后，全部宣告状态从数据库完整重建。

**Why this priority**: 残留即漏洞（幽灵路由指向已离开的节点）。但它依附于 US1/US2 存在，故 P3。

**Independent Test**: 对每条删除路径（撤销 / 退 zone / 被踢 / 删节点 / admin 删用户）各跑一例集成测试，断言三处状态（DB / wg / nft）零残留且合成段可复用；重启服务进程断言重建一致。

**Acceptance Scenarios**:

1. **Given** 宣告已挂接到 zone Z，**When** 主人撤销该挂接且这是最后一个挂接，**Then** 整条宣告删除、合成段回收、peer AllowedIPs 收缩、Z 的防火墙放行移除。
2. **Given** 宣告挂接到 zone X 和 Y，**When** 撤销 X 的挂接，**Then** Y 的挂接与合成段保持有效，仅 X 的防火墙放行移除。
3. **Given** 节点带着宣告退出（或被踢出）其挂接的 zone，**Then** 等价于该 zone 的挂接被撤销，最后一个挂接消失时整条宣告回收。
4. **Given** 节点被删除 / 其主人被 admin 删除，**Then** 名下全部宣告与挂接级联清除，三处状态零残留。
5. **Given** 多条宣告生效中，**When** 服务端重启，**Then** 全部合成段、peer AllowedIPs、防火墙状态从数据库重建，与重启前一致。
6. **Given** 合成段 S1 已随宣告回收，**When** 新的宣告需要同长网段，**Then** S1 可被重新分配。

---

### Edge Cases

- **合成段池耗尽**：新宣告请求被拒绝并返回明确错误（与 IP 池耗尽同类语义）；运维可扩池后重启。
- **配额边界**：用户宣告数达到上限后新宣告被拒（明确错误码）；删除宣告释放名额；运维下调上限只挡新增、不驱逐已有（grandfather，023 同款）；admin 豁免；0=无限。
- **挂接目标 zone 校验**：节点未加入目标 zone 时宣告挂接被拒；宣告者必须是节点主人（他人节点 404，不泄露存在性）。
- **前缀长度边界**：/15 及更大、/31、/32 被拒；恰好 /16 与 /30 合法。
- **非 RFC1918**：公网段、回环、组播、CGNAT 段（与池重叠）一律被拒。
- **宣告节点离线**：成员发往合成段的流量进入隧道后无人应答——属正常现象（与访问离线节点同语义），服务端不做特殊处理；在线状态展示沿用 007。
- **成员自己的 LAN 与某真实网段相同**：不影响服务端（隧道里只有合成段）；消费端体验问题属 033。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 节点注册 MUST 接受客户端自报的平台标识（如 `windows` / `openwrt` / `macos`），持久化到节点记录；本功能上线前已存在的节点读作 `unknown`。节点查询接口 MUST 返回该字段。
- **FR-002**: 宣告相关的全部写操作 MUST 仅对 `openwrt` 平台的节点放行；其他平台（含 `unknown`）返回明确的「平台不支持」错误。能力与平台的对应关系由服务端单点判定，便于将来扩展平台。
- **FR-003**: 服务端配置 MUST 新增合成段池（单个 IPv4 CIDR）；配置校验 MUST 拒绝与 VPN 池重叠的池定义。未配置合成段池时宣告功能整体不可用（宣告 API 返回明确错误），其余功能不受影响。
- **FR-004**: 服务端配置 MUST 新增每用户宣告子网数上限：缺省 10，显式 0 = 无限，负数启动校验失败，admin 豁免（与 023 设备/zone 配额同款三态语义）；超限返回明确错误码；删除释放名额；下调上限只挡新增不驱逐已有。
- **FR-005**: 宣告 MUST 按（节点, 真实子网）唯一建模：首次宣告分配合成段，同一节点把同一真实子网宣告到更多 zone 时 MUST 复用既有合成段（不重复分配）；挂接关系按 zone 独立增删。
- **FR-006**: 合成段分配 MUST 与真实子网等长（/24 配 /24），MUST 全服唯一（不与任何现存合成段及 VPN 池重叠），池内无足够空间时返回明确的「池耗尽」错误且不产生部分状态。
- **FR-007**: 宣告入参校验 MUST 强制：真实子网为合法 IPv4 CIDR 且属 RFC1918；前缀长度在 /16–/30（含）之间；不与 VPN 池、合成段池重叠；与**同一节点**的现存宣告不重叠。**不同节点之间的真实子网允许任意重叠**（本方案核心价值，MUST 有测试钉死）。
- **FR-008**: 服务端 MUST 提供成员可用的接口：向所在 zone 创建宣告挂接（指定自有节点、真实子网）、撤销挂接、查询某 zone 的宣告清单；清单 MUST 含宣告节点标识、真实网段、合成网段三元组（供客户端 UI 展示映射）。非成员查询/操作该 zone 返回与现有 zone 接口一致的错误语义；操作他人节点返回 404。
- **FR-009**: 宣告挂接生效时服务端 MUST 同步数据面：宣告节点对应 WireGuard peer 的 AllowedIPs 增加合成段；zone 的防火墙状态放行「zone 内成员地址 → 该 zone 已挂接的合成段」的新建连接，并放行已建立连接的回程。撤销时对应收缩与清除。防火墙规则语义 MUST 保持现有 zone 间隔离不变（非成员不可达合成段）。
- **FR-010**: 级联回收 MUST 覆盖：显式撤销、节点退出 zone、被 owner 踢出、节点删除、zone 删除、admin 删用户。最后一个挂接消失时整条宣告与合成段一并回收；任何路径后 DB / WireGuard / 防火墙三处零残留；回收的合成段可复用。
- **FR-011**: 服务端重启 MUST 从数据库完整重建全部宣告数据面状态（peer AllowedIPs 与防火墙放行），与重启前一致（SQLite 单一真源，派生态可重建）。
- **FR-012**: 本切片 MUST NOT 改变既有 API 的行为；新增字段/接口对现有客户端向后兼容（旧客户端不传平台标识仍可注册）。
- **FR-013**: 连接方向性 MUST 为单向：仅支持 zone 成员主动连接宣告子网；宣告子网侧主动连接成员不在支持范围（永久非目标，写入设计文档）。
- **FR-014**: DESIGN.md MUST 同 PR 修订：「不做 site-to-site」非目标改为「支持单向子网宣告（合成段映射）」；§11 已知风险登记三条接受项——平台标识由客户端自报可谎报（后果限于宣告不通，不产生越权）、宣告方地址翻译抹掉真实访问源（目标 LAN 只见路由器地址）、宣告内容的社工风险（成员可声称任意内网内容诱导访问）。

### Key Entities

- **宣告（Announcement）**: （节点, 真实子网）→ 合成子网 的唯一映射；属性：宣告节点、真实 CIDR、合成 CIDR、创建时间。生命周期随其挂接集合：最后一个挂接消失即回收。
- **宣告挂接（Zone Attachment）**: 宣告与 zone 的多对多关系行；决定哪些 zone 的成员可达该合成段。
- **合成段池（Synthetic Pool）**: 运维配置的专用 IPv4 CIDR；按需切出与真实子网等长的块，回收复用；与 VPN 池互斥。
- **节点平台（Platform）**: 节点注册时自报的平台标识；宣告能力門檻的判定依据；旧节点为 `unknown`。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 端到端（真实内核网络栈、模拟宣告节点）：zone 成员向合成地址发起的连接 100% 经服务器转发进宣告节点隧道并收到回程；非本 zone 成员发往同一合成段的流量 100% 被丢弃。
- **SC-002**: 两个节点宣告完全相同的真实网段（跨 zone 与同 zone 两种情形）可同时生效，互不抢占：先建宣告的数据面在后建宣告生效前后逐字节不变。
- **SC-003**: 全部六条删除路径（撤销/退 zone/被踢/删节点/删 zone/删用户）执行后，数据库、WireGuard、防火墙三处残留为零，且回收的合成段可立即被新宣告复用。
- **SC-004**: 服务端重启后全部宣告状态自动重建，与重启前对比零差异。
- **SC-005**: 现有全部自动化测试保持绿色（既有 API 行为零回归）；旧客户端（不报平台）注册流程不受影响。
- **SC-006**: 全部非法输入（平台不符 / 超配额 / 非 RFC1918 / 前缀越界 / 与池重叠 / 同节点互叠 / 池耗尽 / 非成员 / 他人节点）100% 被拒且各有可区分的错误标识，无部分状态残留。

## Assumptions

- 宣告端的实际地址翻译（NETMAP + MASQUERADE）发生在 OpenWrt 客户端（032 交付）；本切片集成测试在 netns 中手工配置等价翻译以完成端到端验证。
- 各平台客户端把合成段加入本机路由（动态路由协调器）属 033；本切片只保证服务端数据面与映射查询就绪。在 033 交付前，现有 Windows 客户端因 AllowedIPs 固定为 VPN 大段而无法访问合成段——已知且接受的中间态。
- OpenWrt 客户端本体（注册/隧道/CLI）属 031；本切片的「openwrt 平台节点」在测试中由 API 直接注册模拟。
- 合成段池建议从 CGNAT 空间（如 `100.64.0.0/10` 内不与 VPN 池冲突的子段）划取，写入示例配置与运维文档；具体池大小由运维按客户规模规划。
- 宣告清单的轮询/推送机制不在本切片定义；现有客户端轮询模式（007/011 先例）预计够用，由 033 决定。
- IPv6、DNS 名称解析、宣告审批流均为非目标；LAN 侧主动连接成员为**永久**非目标（FR-013）。
